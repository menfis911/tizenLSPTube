# LSPTube

Автономная адаптация TizenTube для проектора **Samsung The Freestyle SP-LSP3BLAXCE**.

LSPTube запускает собственную сетевую службу, проверяет готовность прокси и открывает телевизионный интерфейс YouTube с дополнениями TizenTube. Mac нужен для установки, а не для просмотра. **Host PC IP можно оставить адресом Mac**: значение `127.0.0.1` для внедрения скрипта не используется.

Это независимый производный проект, не связанный с Samsung, Google, YouTube или авторами исходного TizenTube. Основа — [reisxd/TizenTube v2.1.1](https://github.com/reisxd/TizenTube/tree/v2.1.1), автор Reis Can и участники проекта. Мы сохраняем их авторство и GPL-3.0-only.

## Состояние

Пользователь подтвердил на **Tizen 6.5 / T-KSU2EPWWC-1720.7** запуск двухкомпонентного прототипа и наличие настроек TizenTube. Длительные испытания, восстановление после сбоев и другие модели не проверены. Новый брендинг и сборки требуют отдельной проверки на проекторе.

**Текущий выпуск содержит два устанавливаемых WGT:** `LSPTube` — основной ярлык со службой; `LSPTube Engine` — оболочка Cobalt. Открывать нужно **LSPTube**. Одно приложение/один WGT пока не реализованы: Cobalt перехватывает запуск пакета с native-метаданными, обходя HTML-загрузчик. Общий ZIP не является одним устанавливаемым приложением.

## Установка

1. Соберите пакеты по инструкции ниже или скачайте их из опубликованного выпуска, если он доступен.
2. В Apps2Samsung установите **Engine**, затем **LSPTube**, включив **Partner Signing**. WGT в этом проекте неподписанные: установщик подписывает их вашим сертификатом.
3. Developer Mode оставьте включённым, Host PC IP — адресом компьютера для установки.
4. Отключите питание проектора на 10 секунд, включите и откройте **LSPTube**.
5. После появления интерфейса YouTube проверьте настройки TizenTube внутри настроек YouTube или зелёной цветной кнопкой пульта.

Первый выпуск по умолчанию настроен на IP проектора **192.168.100.95**. Закрепите этот адрес в DHCP роутера или соберите пакет с фактическим IP. При изменении адреса требуется новая сборка Engine.

Не удаляйте обычный YouTube: приложение использует встроенный Samsung Cobalt. Старые прототипы имеют те же идентификаторы и заменяются обновлением. Чужие сертификаты, пароли и токены не включены.

## Сборка и проверки

Требуются Python 3.9+ и Node.js для тестов. Дополнительные зависимости для упаковки не нужны.

```sh
node tests/test-start.cjs
node tests/test-https.cjs
python3 scripts/build.py --projector-ip 192.168.100.95
```

Результат: `dist/LSPTube-0.7.0.wgt`, `dist/LSPTube-Engine-0.7.0.wgt`, `dist/LSPTube-0.7.0-install.zip` и контрольные суммы. Пакеты не содержат сертификатов и не устанавливаются автоматически.

Для изменения дополнений и перевода нужен Node.js 22: выполните `sh scripts/build-userscript.sh`, затем упаковку. Готовые runtime-файлы сохранены, поэтому для простой упаковки npm не нужен. Рабочая схема запуска остаётся двухкомпонентной; эксперимент с одним приложением сохранён в отдельной ветке.

## Голосовой перевод — эксперимент 0.7.0

На Freestyle нативный MP3 был отклонён с error 4. В 0.7.0 MP3 декодирует встроенная служба Node 12, а Cobalt воспроизводит короткие PCM-буферы через Web Audio. Mac, внешний сервер и установка FFmpeg не требуются. Первичная загрузка и подготовка звука могут занять до 60 секунд; ручная проверка доступна сразу. Путь проверен до получения PCM-сигнала, звук на самом проекторе ещё требует подтверждения.

При HTTP 403 на подписанном запросе Яндекса приложение один раз создаёт новый сеанс и повторяет запрос. Если отказ сохраняется, сообщение показывает этап: создание сеанса, запрос перевода или подготовка аудио. Это не обходит сетевые ограничения Яндекса. Проверка сохраняет точную ошибку даже до создания аудиоплеера. VPN на Mac не гарантирует такой же сетевой маршрут у проектора.

При обновлении с 0.4.0 достаточно установить новый `LSPTube-0.7.0.wgt` и перезагрузить проектор; Engine можно оставить прежним. Сообщение «включён» требует движения аудиодорожки. Кнопка **Проверка звука перевода** в настройках воспроизведения или LSPTube открывает состояние плеера вручную. Экран выводится непосредственно поверх YouTube; таймер запуска не зависит от готовности основного видео. Если звук не запускается за 60 секунд, появится экран проверки с состоянием плеера.

Откройте иностранный ролик, затем **настройки воспроизведения → Перевести на русский**. Повторное нажатие выключает перевод. Кнопка также есть в настройках LSPTube. Яндекс получает ссылку на ролик и его длительность; аккаунт и ключ API не нужны. Запрос выполняется на проекторе, без Mac или чужого сервера-посредника.

Поддерживаются обычные видео до четырёх часов. Подготовка может занять несколько минут. Исходный звук приглушается только после запуска перевода и восстанавливается при отключении или ошибке. Реализована синхронизация с паузой, перемоткой и скоростью воспроизведения. При переходе к другому ролику перевод отключается. Частичный перевод помечен отдельно; после окончания доступной части можно повторить запрос позже.

Реальный запрос вернул аудио перевода для публичного тестового ролика `jNQXAC9IVRw`, скачивание аудио по HTTPS проверено. **Одновременное воспроизведение на Cobalt/Freestyle ещё не проверено**: сборка предназначена для испытания на проекторе. Некоторые ролики Яндекс отклоняет или требует входа; авторизация, платные голоса и прямые эфиры не реализованы. Используется неофициальный API, его доступность может измениться.

Проверенная исходная пара полностью сохранена в `baselines/working-autonomous-source-2026-11-01.zip`. Ранний тег `baseline-working-2026-11-01` не включал runtime-файлы из-за правила игнорирования; для восстановления используйте архив, а не тот тег. Происхождение компонентов, способ пересборки сетевой службы и границы воспроизводимости описаны в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Ограничения и планы

- Один WGT — исследование совместимости, не готовая возможность.
- Перевод речи через Яндекс — эксперимент, требует проверки звука на проекторе.
- Дополнения для Cobalt теперь встроены в пакет и загружаются из собственной службы; сетевые сервисы YouTube, SponsorBlock и Яндекса по-прежнему внешние.
- Прокси слушает локальную сеть, как в исходном TizenTube. Используйте доверенную домашнюю сеть, не публикуйте порт 8101 в интернет.
- Вход в аккаунты, трансляция с телефона/DIAL, обновления и длительное воспроизведение новой версии не проверены.

### Загрузка и баланс звука

В настройках воспроизведения выберите **Яндекс Перевод · звук и загрузка**. Здесь сохраняются громкость оригинала (0–100%, по умолчанию 5%), перевода (25–100%, по умолчанию 100%) и пауза до готовности (по умолчанию включена). При выключении перевода исходная громкость восстанавливается. Настройки доступны также в меню LSPTube.

Индикатор показывает подготовку Яндексом, фактический процент скачивания при известном размере и подготовку PCM. При неизвестном размере показывается этап без процента. Ролик, который уже был на паузе до запроса перевода, автоматически не запускается.

### Проверка непрерывного AAC (0.7.0)

После перезагрузки откройте ролик без включения перевода. В настройках воспроизведения → **Яндекс Перевод · звук и загрузка** выберите **Проверка AAC · файл**. В течение 20 секунд должен звучать ровный двухтональный сигнал одновременно с роликом. Затем появится экран результата. ОК/Назад закрывает результат; Назад во время проверки останавливает тест. Повторите с **Проверка AAC · MediaSource**.

Это отдельная проверка совместимости, а не новая реализация перевода. Файлы встроены, внешний сервер и FFmpeg на проекторе не нужны. Сигнал должен быть непрерывным, а YouTube — продолжать воспроизведение; продвижение часов само по себе не доказывает слышимый звук. Результат на Freestyle ещё не проверен.
